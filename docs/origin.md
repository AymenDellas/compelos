# ORIGIN

ORIGIN is the Compel OS workstation for researching public coaching-business opportunities. Its queue, evidence and publication policy are separate from the LinkedIn qualification engine. The local worker reuses the existing PostgreSQL pool, the two public research lanes and their shared three-request limiter. ORIGIN takes at most one research lane and opens at most one disposable Chrome browser at a time. The ORIGIN API uses the existing loopback admin guard and requires same-origin JSON mutations.

Start Run reads recent coaching promotions through the keyless Searchia web index and public WordPress Reader tag index. It uses no credentials, search credits or AI requests. Index records supply candidate URLs. ORIGIN reopens the public promotion and verifies the official paid coaching offer, eligible market, and buyer path before it queues a business. A hosted event can lead to a business only when its organizer points to the official website and the verified offer links back to that event. Calendar and event hosts never become the business. Discovery reports screening failures and rotates its bounded tag queries. PostgreSQL retains source cursors, request receipts and deduplication history. [Searchia API](https://www.searchia.com/api/) · [Public Reader endpoint](https://developer.wordpress.com/docs/api/1.1/get/read/tags/%24tag/posts/)

## Run it

Install the repository dependencies including the local worker's development dependencies. Run the dashboard and agent from the checkout.

```powershell
npm run dev
npm run worker
```

In Compel OS, open **Acquisition → ORIGIN → Start run**. The first start or settings save applies the additive schema. Operations controls the schedule, research limits and desktop/mobile capture. Pause, resume, and cancel act on the saved run. The local agent and machine must stay online for scheduled work. With the agent offline, a queued run remains in PostgreSQL.

To search for a specific number of ready opportunities, set **Qualified opportunities target** in Operations. **New businesses per batch** controls the size of each batch. A positive target continues into fresh batches under the same run and stops as soon as enough distinct, current, unsuppressed opportunities pass all seven gates. An empty target runs one batch. The configured time budget applies across batches. A goal run pauses at that deadline. Resume grants a new time window and continues the same target and checkpoints. Each batch has a bounded public index and site screening allowance. The run reports a shortfall if a full discovery attempt returns no new businesses.

## CLI

```powershell
node origin.cjs help
node origin.cjs doctor
node origin.cjs sources probe
node origin.cjs run --qualification --require-qualified
node origin.cjs run --qualified-target 3
node origin.cjs evaluate latest
```

Use `migrate` to update an earlier installation. `doctor` reports the deployed worker policy and automatic discovery readiness. Start Run and its CLI equivalents discover their own publisher sources and always apply the seven qualification gates. `--require-qualified` exits with code 5 when a completed run has no current ready opportunity. `--qualification` is retained for compatibility with existing commands.

`start` queues work for the Compel worker. `run` queues and follows the named run. `work active` continues saved work, and `wait` follows progress without claiming stages. If the persistent agent is offline, `run` and `work` can drive a single ORIGIN run using its normal PostgreSQL lease. They reuse the persistent agent when it is online. A foreground run ends after the named run and leaves recurring scheduling to the persistent agent. Use `pause`, `resume` and `cancel` with an ID or `active`. Ctrl+C leaves the saved run available for continuation.

`runs`, `show-run`, `investigations`, `opportunities`, `dossier`, and `evidence` read the same PostgreSQL records as the dashboard. Export screenshot bytes with `artifact <investigation-id> <artifact-id> --output <new-file>`. The CLI checks the SHA-256 before writing and refuses to overwrite a file. `settings set` changes one value, `settings import` applies a JSON patch, and `schedule every 90` or `schedule off` controls future runs. `usage`, `evaluate`, and `evaluations` report costs, per-gate blockers, and benchmark results. Output is JSON and progress goes to stderr. Run `node origin.cjs help` for arguments.

`sources probe` runs automatic discovery, checks supplemental feeds when present, and displays source decisions. `sources history` reports stored outcomes and official identity corroboration. Operator-approved supplemental feeds are optional. When adding one, record its reuse terms and use a shared `--publisher` value for feeds with the same owner.

```powershell
node origin.cjs sources add "Publisher name" "https://publisher.example/feed" "https://publisher.example/terms" --publisher "publisher-owner"
node origin.cjs sources list
```

The schedule starts disabled. New settings allow 36 candidates and 30 minutes by default, with configurable ceilings of 72 candidates and 75 minutes. The local UI and CLI snapshot these settings per run. Positive scheduled intervals are in minutes. A paused run occupies the active slot. For a stopped process, another owner can continue after the lease expires. The previous lease and control revision cannot commit a checkpoint after a control change. Older model settings and usage receipts can still be read for compatibility and historical reporting.

## Data and verification

Every run uses PostgreSQL history to screen discoveries by normalized website domain and known Wikidata identity. A business is eligible for a new run until its first investigation stage starts. ORIGIN records the start before reading the site, keeps the record across failures and cancellations, and also recognizes progress saved by prior versions. Discovery rounds save their query cursors and distinct candidates together. Paused or interrupted work can continue within its original run. Overview shows the number of candidates queued against the saved run target. The Opportunities tab keeps saved qualified dossiers visible and shows **Needs recheck** after the evidence expires. The ready count uses current evidence and the tab keeps CRM-suppressed businesses out of its results.

1. Public discovery ranks recent promotions from bounded topic queries and skips businesses already processed. The worker only queues a business after reading the actual promotion and confirming its paid offer, market and buyer path. Older discovery adapters remain available for historical reports and source probes.
2. `research.ts` corroborates identity on the official entry or linked About pages. Search candidates need first-party branding. When search lands on a deep offer page, the investigator also checks the official homepage for market, history and contact context. It follows same-site case-study links from case indexes, including links labeled “Read more,” and requires evidence of the investigated provider delivering the engagement. It checks up to three public booking destinations, including officially linked YouCanBookMe pages. Broken and expired booking paths need an independent recheck and evidence that there is no viable alternate route. A material duration mismatch or a direct booking promise that leads to a generic message form can qualify when both observations reproduce and the reported alternative is absent from the inspected destination. Access restrictions and interactive-only controls are recorded. The investigation stops at form submission boundaries.
3. `policy.ts` applies the seven evidence gates. Official service regions or a structured operating address can establish an eligible market. Commercial substance requires two supporting measures across credible pricing or a client engagement, durable operating history, and a substantive program. The current discovery lane requires a dated, independently re-read promotion linked to the exact verified paid offer. Historical runs can also carry independent publisher observations. A published general business inbox or inquiry form can establish contact readiness, subject to restrictions observed on the site. Traffic, deliverability, revenue, conversion loss, and ability to pay remain unknown. A confirmed exclusion rejects. Missing, conflicting or expired proof stays unresolved. Only fresh opportunities under the current policy appear in the ready view.
4. PostgreSQL owns `origin_settings`, `origin_runs`, `origin_businesses`, `origin_identity_keys`, `origin_investigations`, `origin_artifacts`, `origin_model_usage` and `origin_evaluations`. Investigations hold checkpointed JSON claims, source relationships, journey steps, evidence hashes, dated observations and the adjudicated decision. Stable business IDs key the in-app pipeline. Same-host variants and recurring Wikidata IDs deduplicate across runs. Conflicting website evidence for a new candidate stays unresolved. The read-only `readyOpportunities()` contract serves only fresh, current, unsuppressed records for future in-app consumers. ORIGIN does not insert LinkedIn leads or invoke any outreach action. Later CRM suppression immediately removes the matching business from the ready view.

ORIGIN prioritizes dedicated offer pages and reads linked first-party testimonials and corroborated landing subdomains. Attributed accounts of coaching delivered to clients from two distinct named organizations can establish repeat client work. The investigator follows first-party publication archives. A dated coaching article can support acquisition when its body links to the verified offer or a public consultation route. Direct booking promises are checked across the bounded set of destinations and independently rechecked if they lead to unrelated content. Public Acuity selector links retain numeric calendar and appointment identifiers after validation. An explicitly explained callback remains a valid inquiry journey. The evaluation report distinguishes queued, investigated, and completed candidates.

The public transport pins validated DNS addresses, rejects local and restricted destinations, checks redirects and publisher scope, reads robots rules, and keeps a conservative per-host document gap. Browser network access goes through the same reader. Captures admit the observed page and a bounded set of passive same-site resources, so some views report missing assets. No forms are submitted. One screenshot per device is persisted by content hash. The next available worker sweep removes image bytes after 30 days while retaining capture metadata. Trace records are bounded HTTP observations and resource-state notes. Full browser traces, HTML archives and behavioral analytics are outside this implementation.

The automatic publisher adapter admits factual citations when a public source's access and use conditions allow the bounded read. A missing license for expressive content does not bar an otherwise supported fact citation. It checks declared site terms and refuses blocked or challenged pages, applicable automation or commercial-use restrictions, unreadable declared terms, and syndicated or unattributed records. It requires the publisher's own recent dated record and an explicit subject-to-business link. The ledger retains the relevant facts in ORIGIN's own words, the source URL, applicable terms links, observation time and a digest. It retains no publisher article titles, bodies, images, audio or transcripts. Published facts stay distinct from database extraction and content reuse. Current publisher checks can be reused for up to 24 hours. ## AgentRouter

ORIGIN reuses the existing AgentRouter integration and defaults to `gpt-6.1-sol` on the Responses route. `ORIGIN_AGENTROUTER_MODEL` overrides the model for ORIGIN. Before reserving a request, ORIGIN reads the selected route's public token rates, applies the largest published group multiplier and a safety margin, and calculates a reservation against the bounded input and output. `ORIGIN_AGENTROUTER_MAX_CENTS` limits that reservation to 50 cents by default. The provider's published model ratio of 4, completion ratio of 5, and default group ratio of 1 produced a 48-cent reservation during validation. The response uses a bounded structured analyst verdict. ORIGIN uses the verdict to prioritize a targeted acquisition read for an appropriate candidate. The dossier links the review to current evidence. Deterministic checks own the eligibility decision. [AgentRouter catalog](https://agentrouter.org/api/pricing) · [Quota formula](https://docs.newapi.ai/en/docs/guide/console/settings/rate-settings)

The database reserves the full configured bound before dispatch and retains it even if the result is lost. ORIGIN permits one upstream request per reservation, one active request and one request per minute. It caches matching summaries and records classified failures, bounded cooldowns, and any reported token count available in response usage frames. Authentication and quota failures open a longer cooldown. Rate limits use Retry-After where supplied. Unknown provider costs remain unavailable. The reserved amount shown in Operations is a conservative budget reservation. The live acceptance opted out of inference and did not verify live quotas, billing or model output.
